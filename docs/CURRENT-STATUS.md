# RainbowThreeMatch 현재 상태

기록일: 2026-11-26 (한국 시간). 이 문서는 구현·검증·제안을 구분한 인수 기록이다.

## 병합 작업

사용자가 열린 PR 전체 병합과 푸시를 요청했다. PR #5~#14는 모두 원격 main에 병합됐다. 이 상태 문서는 PR #15로 게시했다. 최신 상태와 후속 작업은 [이슈 #16](https://github.com/luos1/RainbowThreeMatch/issues/16)에 기록한다. 사용자 요청에 따라 저장소 Issues 기능을 활성화했다.

## 구현된 게임

- Unity 2022.3.8f1 프로젝트 루트는 `Rainbow/`다.
- 기존 세로 퍼즐 `02.Game`은 유지한다. 매칭·제거·보충·점수·타이머·종료·Retry와 HUD 가림 수정, 폭발 연출 및 Kenney CC0 효과음이 있다.
- 별도 가로 태블릿 모드 `03.TabletPuzzleShooter`는 왼쪽 퍼즐과 오른쪽 자동 슈팅을 결합한다. 플레이어는 움직이지 않는 거대 모함이며 선체 일부와 포문만 보인다.
- 공격 블록 N개 제거는 색에 맞는 탄환 N발로 연결된다. 빨강 직선, 주황 관통, 노랑 확산, 하늘 유도, 보라 폭발이다. 초록은 블록당 체력 1 회복, 파랑은 블록당 쉴드 0.75초(최대 6초)이며 탄환을 추가하지 않는다.
- 적은 곡선 편대로 진입하고 실제 적탄 충돌로 모함에 피해를 준다. 60초 출격, 편대·보스 보상, 결과·격납고·공격/체력 강화·재출격 흐름이 있다. 강화 저장은 로컬 PlayerPrefs 시제품이다.
- 태블릿 블록은 효과 아이콘을 사용한다. 원래 세로 퍼즐의 얼굴 이미지는 보존한다.
- 팔레트는 매치 시작부터 보충 완료까지 고정하고 새 방어 블록 공급을 예고한다. 매치 실패는 유효한 입력만 집계하며 성공 시 연속 실패를 초기화한다.

## 아직 해결되지 않은 플레이 피드백

현재 3회 실패 패널티는 다음 예정 소형 편대에 추가 기체를 붙이는 구현이다. 즉시 폭젠이 아니므로 사용자는 발동을 알아보기 어렵다고 보고했다. 다음은 요청되었지만 아직 구현되지 않았다.

1. 2회 실패 시 뚜렷한 위기 경고와 진입 방향 표시.
2. 3회 실패 직후 실제 두 배 편대가 들어오는 즉각적인 압박과 안전한 개체 상한.
3. 큰 매치·연속 성공의 강한 포격 보상. 공격 블록 수와 탄환 수의 일치는 유지한다.
4. 적 역할에 따른 색 선택, 편대 조기 격파 뒤 긴 대기 축소, 보스 공격 예고와 반격 구간.
5. 강화 단계가 포문 외형·사격음·격추 반응에서도 드러나는 변화.

기능 검사 통과를 재미의 증거로 취급하지 않는다. 위 변경은 실제 한 판의 입력·위기·회복·반격을 플레이하며 다시 평가해야 한다. 세부 수치와 효과는 확정된 구현으로 간주하지 않는다.

## 검증과 한계

- 기존 PR #14 검증 SHA: `e2a9348f7108463b11abf14fd2fe2112a38154b4`. 해당 보고서의 Unity Play Mode 결과는 80 통과, 실패·건너뜀 0이다.
- 기존 태블릿 1024×768·1133×744 및 세로 360×640 검증은 Unity Editor의 EventSystem 입력·고정 시나리오를 포함한다. 실제 손가락·기기 성능·스피커 검증과 구별한다.
- 실제 Google OAuth와 계정별 최고점 저장은 전용 인프라·OAuth·서명 설정이 없어 미검증이다. 테스트 더블을 사용한 인증 흐름 검증은 실제 Google 로그인 성공을 뜻하지 않는다. 인프라 인계는 `AI-HANDOFF.md`, 인증 설정은 `google-sign-in.md`를 참고한다.
- 사용자는 iPhone Simulator 사용과 테스트를 취소했다(항목 18). 재개하지 않으며 설치 도구와 기존 자료는 보존한다. Rainbow 앱의 Simulator 실행 성공은 확인되지 않았다.
- PR 점검 시 GitHub 등록 CI 검사와 리뷰는 없었다. 검사 0건은 CI 통과를 뜻하지 않는다.
- 개발 후속 작업은 항목 24에 남아 있다. 이 세션의 OMX 사전검사 `unsupported_documented_leader_proof`는 해당 실행 경로의 차단이며 게임 테스트 실패와 구별한다.
