# 태블릿 모함 방어전 계획

> 기존 Orca 전담 워커가 writing-plans와 TDD를 적용해 단계별로 실행합니다.

**목표** 거대 모함 아래쪽에서 퍼즐을 조작하고, 여러 편대의 소형기가 몰려드는 위협을 수리·방어막·무기로 버팁니다.

**구조** 기존 60초, 3웨이브, 네 편대와 보스의 정산·격납고 흐름을 사용합니다. 모함은 화면 하단 정중앙에 고정합니다. 오른쪽 전장 하단에 큰 선수와 세 포문만 노출하고 포문이 자동으로 조준합니다. 화면에 드러난 선체 또는 방어막에 실제 적탄이 닿을 때만 접촉을 처리합니다. 같은 공격색 블록 수만큼만 발사하며 포문은 여러 곳을 교대로 사용합니다.

- [x] `TabletCombatTests.cs`에 초기 다섯 기 동시 진입과 첫 적탄 비행 중 HP 불변을 회귀 테스트로 고정합니다.
- [x] `TabletCombat.cs`에서 5·5·6·7기 편대와 1기 보스로 늘립니다. 소형 적은 1–2HP, 보스는 9HP를 시작값으로 잡고 4개의 편대 보상과 보스 보상을 유지합니다. 발사 대기와 조준·포구 시각은 이전 색별·초당 12발 상한을 따릅니다.
- [x] `TabletHostileFire.cs`에 상한 32개의 풀과 고정 선체와 이동하는 적탄의 선분 충돌, 놓친 탄 제거, 쉴드 차단, 0.35초 무적시간을 둡니다. 일반 적은 예고 후 한 발, 보스는 간격을 두고 부채꼴 탄을 발사합니다. 화면 밖에서 새 탄을 발사하지 않습니다.
- [x] `TabletView.cs`, `TabletSortieView.cs`에서 적 수를 모델과 연결하고 적 탄·포구 섬광·차단과 피격을 전장 안에 표시합니다. 모함은 선체가 읽히는 큰 크기를 유지하며 작은 기체는 사이에 간격을 둡니다. 생성한 모함 PNG는 기존 리소스 옆에 두고 직접 알파를 검사합니다.
- [x] `Game.cs`에서 기존 초록의 첫 유효 그룹과 같은 방식으로 파랑이 해금된 뒤 한 번 파랑 그룹을 확보합니다. 초록 수리량, 파랑 지속·상한, 색 순환은 유지합니다. 태블릿 블록의 낙하 시간을 기존의 68%로 줄여 정상 플레이에서 보충 대기를 측정합니다.
- [x] Unity 2022.3.8f1 전체 PlayMode와 4:3·mini Game View 정상 속도 검증을 실행합니다. 무입력·탄 부족·방어 사용·강화 적용, 쉴드 차단과 미스, Retry·씬 종료, 격납고 원장과 발사량을 기록합니다.

기반은 PR #11이며 초기 수치는 튜닝 값입니다. PR에는 실제 게임 장면과 무입력·방어 조건의 측정값을 정리합니다.

전투 손맛·실제 검증을 우선하므로 강화 단계별 추가 함선 외형은 이번 변경에서 보류합니다.
