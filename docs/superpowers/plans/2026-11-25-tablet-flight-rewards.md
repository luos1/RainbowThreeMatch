# iPad 출격·보상·격납고 구현 계획

> 기존 Orca 전담 워커가 이 계획을 단계별로 실행합니다. 체크박스는 구현과 검증 진행을 기록합니다.

**목표** 준비 화면에서 출격한 플레이어가 편대와 최종 보스의 보상을 받고, 정산을 거쳐 기체를 강화하고, 강화된 기체로 같은 훈련에 재출격하게 합니다.

**구조** `TabletCombat`은 현재 출격에서 완료된 보상 대상을 기록합니다. `TabletProgress`는 출격 식별자와 지급 기록을 보유량·강화 단계와 함께 로컬에 저장합니다. `TabletScene`이 준비·전투·정산·격납고 전환을 관리하고 `TabletView`가 전투 신호와 각 단계의 버튼을 표시합니다.

## 확정 규칙과 시제품 기본값

퍼즐만 직접 조작합니다. 기존 편대를 전멸시키면 보상을 받고 마지막 정예를 보스로 격파하면 더 큰 보상을 받습니다. 기체 강화는 플레이어가 선택합니다. 기존 60초, 3웨이브, 적 HP 합계 32, 초당 최대 12발, 공격색 N개당 N발, 초록 1HP/칸, 파랑 0.75초/칸과 6초 상한을 유지합니다. HP 0이 같은 틱의 전멸이나 시간 종료보다 우선합니다. 보스 격파 후 남은 편대가 있으면 전투를 이어가고, 시간 내 생존하면 격파와 구분해 정산합니다. 세로 퍼즐, 인증과 외부 인프라는 별도입니다.

아래 수치는 시제품 기본값입니다. 패배해도 플레이 중 지급된 편대 보상은 남습니다. 실제 계정 동기화, 결제, 외부 통화는 범위 밖입니다.

| 대상 | 시제품 지급·비용 | 효과 |
| --- | ---: | --- |
| 편대 1·2·3·4 | 20 / 20 / 30 / 35 | 해당 편대의 모든 기체 격파 후 회당 1회 |
| 최종 보스 | 75 | 보스 HP가 0에 도달했을 때 회당 1회 |
| 공격력 I·II·III | 40 / 75 / 115 | 기본 피해에 각각 +10% / +20% / +30% |
| 최대 체력 I·II·III | 35 / 70 / 110 | 다음 출격에서 최대 체력 11 / 12 / 13 |
| 출격 전환 | 최소 0.55초 | 기존 블록 준비와 병행하고 타이머는 조작 가능 시점부터 시작 |
| 연속 구매 잠금 | 0.25초 | 구매 직후 새 가격을 표시하고 짧은 연속 탭의 차감 방지 |

## 단계와 파일 책임

1. `Rainbow/Assets/Scripts/Tablet/TabletCombat.cs`에 편대·보스 완료 비트와 보스 표시 상태를 제공합니다. 이미 쓰는 적 HP와 편대 번호로 묶고 미등장 후속기도 편대 전멸 검사에 포함합니다. 공격력은 기존 색별 직접·추가 피해에 동일 배수로 적용하고 초록은 바뀐 최대 체력까지만 1HP/칸을 회복합니다.
   - [x] 편대 선두 단독 격파에서 지급 0, 전멸에서 편대 비트 1회, 최종 정예 격파에서 보스 비트 1회, 전멸/패배/시간의 기존 우선순위 회귀 검증.
2. `Rainbow/Assets/Scripts/Tablet/TabletProgress.cs`가 `BeginRun()`, `Credit(run, mask)`, `Buy(upgrade)` 및 가격과 적용 수치를 담당합니다. `Rainbow.TabletProgress.v1` 한 스냅샷에 버전, 잔액, 두 강화 단계, 현재 출격 ID와 지급 비트를 저장합니다. 이전 출격의 이벤트와 이미 지급된 비트는 무시하고 손상된 값은 기본 상태로 읽습니다. 고유 테스트 키를 사용합니다.
   - [x] 재로딩 및 결과 재진입 시 중복 지급 0, 오래된 출격 무시, 음수·포맷 오류 복구, 구매 차감·한도·잔액 부족과 다음 세션 저장 회귀 검증.
3. `TabletScene.cs`와 `Game.cs`에 준비 → 짧은 발진 → 전투 → 정산 → 격납고 → 같은 훈련 재출격을 연결합니다. 준비와 격납고에서 현재 능력을 표시하고, 정산은 획득량과 보유량을 분리합니다. 정산은 전투 종료 경로마다 열리고 구입은 격납고에서만 받습니다. 다음 출격 시작 시 확정된 강화 값을 읽고 보드·탄·효과·쉴드를 초기화합니다.
   - [x] 정산과 격납고에서 퍼즐 입력·타이머 정지, 연속 버튼에서 중복 시작·차감 없음, 씬 재진입 시 보유량·강화 유지와 60초 초기화.
4. `TabletView.cs`와 전환 화면 구성에 보스 예고, 전장 상단 체력바, 편대/보스 보상 피드백, 결과 주행동 `정비하기`, 격납고 주행동 `다시 출격`을 연결합니다. 기존 기체와 파괴 애니메이션을 재사용하고 가로 안전영역을 유지합니다.
   - [x] Unity 2022.3.8f1에서 전체 PlayMode. 1024×768과 1133×744 실제 Game View에서 EventSystem 입력으로 준비·편대·보스·정산·강화·다음 출격 확인. 결과 화면과 강화 전후를 캡처하고 연속 시연 영상에 입력 및 실제 로컬 재로딩 로그를 남깁니다.
